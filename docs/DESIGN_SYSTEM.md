# Дизайн-система «Работяга»

## Принципы

Интерфейс должен ощущаться как нативное приложение iOS: ясный, спокойный,
предсказуемый и быстрый. Содержание важнее декоративных эффектов. Системные
компоненты SwiftUI, жесты и переходы предпочтительнее собственных аналогов.

Базовая тема тёмная. На текущем этапе приложение принудительно использует тёмную
схему; перед публичным релизом это решение нужно повторно проверить с учётом
[Apple Dark Mode guidance](https://developer.apple.com/design/human-interface-guidelines/dark-mode).

## Токены

### Цвет

- `surfacePrimary`: системный `systemBackground` в тёмной схеме.
- `surfaceSecondary`: `secondarySystemBackground`.
- `surfaceElevated`: системный material либо `tertiarySystemBackground`.
- `textPrimary`: `.primary`; `textSecondary`: `.secondary`.
- `accent`: фирменный оранжевый из `AccentColor.colorset` — только для основного
  действия и активного состояния.
- `info`: системный cyan/blue; `success`: системный green; `warning`: системный
  orange; `danger`: системный red.

Не полагаться только на цвет: статус всегда сопровождается текстом или SF Symbol.
Не копировать числовые значения системных цветов — использовать semantic API.

### Типографика

- Использовать semantic styles: `.largeTitle`, `.title`, `.headline`, `.body`,
  `.callout`, `.footnote`.
- Основной текст — `.body`; подписи — не меньше `.footnote`.
- Фиксированный размер допустим только для декоративного символа; текст должен
  масштабироваться через Dynamic Type.
- Поддерживать перенос строк и accessibility sizes без обрезки основной команды.

### Пространство и форма

- Шаг сетки: 4 pt. Типовые интервалы: 8, 12, 16, 24, 32 pt.
- Горизонтальный отступ экрана: 20–24 pt; на компактных экранах не меньше 16 pt.
- Touch target: минимум 44×44 pt.
- Скругления: 12 pt для компактных контролов, 16–20 pt для карточек и панелей.
- Тени использовать редко; глубину преимущественно выражать системными
  поверхностями и materials.

## Компоновка

- Контент соблюдает safe areas. Фон может уходить под системные области, но текст,
  кнопки и поля — нет.
- Dynamic Island не является контейнером приложения. Не размещать рядом с ним
  критические элементы и не имитировать его форму.
- При появлении клавиатуры сохранять доступ к полю ввода и кнопке отправки через
  `safeAreaInset`, `ScrollView` и системное keyboard avoidance.
- Главные действия размещать в средней или нижней части экрана, достижимой одной
  рукой. Верхняя панель — для навигации и вторичных действий.
- Интерфейс должен работать на iPhone 15 Pro (393×852 pt) и компактной ширине;
  ориентацию и размер нельзя определять по конкретной модели устройства.

## Навигация будущего продукта

Пока приложение одноэкранное, навигационный shell не вводится. При появлении
реальных модулей использовать небольшой стабильный набор верхнеуровневых зон:

1. **Работяга** — чат и основное голосовое действие.
2. **Задачи** — история запусков, текущий статус и результаты.
3. **Устройства** — компьютеры и подключённые сервисы.
4. **Настройки** — профиль, безопасность, уведомления и подключения.

Голосовой режим открывается из чата как заметное действие, а не дублирующий tab.
Уведомления показываются через системный inbox/центр активности и deep links.
Количество tabs не должно расти вместе с количеством функций. Внутри каждой зоны
используется системная иерархическая навигация; временные задачи открываются sheet.

Проект имеет deployment target iOS 15. Новые SwiftUI API (`NavigationStack`, новый
`Tab` API, новые symbol effects) разрешены только после поднятия target либо с
явным availability fallback.

## Компоненты

- **PrimaryButton**: один prominent button на экран, глагольная подпись, accent
  background, высота не меньше 50 pt.
- **StatusBanner**: SF Symbol + короткий текст; success/warning/error различаются
  не только цветом.
- **MessageBubble**: контент сначала, действия доступны через системное context
  menu; длинный текст выделяется и масштабируется.
- **TaskRow**: название, краткий статус, время, disclosure indicator только если
  строка действительно открывает экран.
- **ConnectionRow**: сервис/устройство, состояние, последнее соединение, системный
  toggle или отдельное действие — не оба сразу.
- **VoiceControl**: понятные состояния idle/listening/processing/error, текстовая
  альтернатива и явная остановка записи.

## Motion и обратная связь

- Использовать системные переходы. Анимация объясняет изменение состояния, а не
  украшает экран.
- Микроанимации — 150–250 ms; длительные операции показывают ProgressView и могут
  быть отменены, если это безопасно.
- Уважать `accessibilityReduceMotion`; не использовать бесконечные декоративные
  анимации, автоскролл и резкие вспышки.
- Haptics добавлять только к важному подтверждению или ошибке, не к каждому tap.

## Accessibility checklist

- Все интерактивные элементы имеют понятные label, value и при необходимости hint.
- Декоративные изображения скрыты от VoiceOver; значимые не дублируют соседний
  текст.
- Порядок VoiceOver соответствует визуальному порядку.
- Проверены все Dynamic Type sizes, Bold Text, Increase Contrast, Reduce Motion и
  Reduce Transparency.
- Основной текст имеет достаточный контраст; цвет не является единственным сигналом.
- Ошибки формулируются рядом с проблемой и предлагают конкретное исправление.
